# rules.md

规则描述在此：
本规则用于约束 AI 在修改、补充、测试和重构本项目代码时的行为方式，目标是保证生成或修改的代码符合 Java 17 与 Spring Boot 3
的规范，逻辑清晰、上下文一致、结构合理，并避免出现低级错误或破坏现有功能。

## 指导原则

- 所有生成或修改的代码必须符合 Java 17 与 Spring Boot 3 的语言特性与最佳实践，不得使用已废弃或不推荐的写法。

- 在编写或修改代码前，必须先理解已有代码结构、类职责与调用关系，避免破坏上下文一致性或引入逻辑冲突。

- 修改代码应尽量保持最小影响范围（最小侵入原则），避免不必要的重构或无关改动。

- 所有逻辑变更必须保证语义正确、边界条件明确，并考虑异常情况与失败路径。

- 禁止引入明显的低级错误，包括但不限于空指针风险、资源未关闭、并发安全问题、明显的类型或状态错误。

- 新增代码应遵循现有项目的风格（命名、日志方式、异常处理、包结构），保持整体风格一致。

- 在不确定需求或上下文时，应给出假设说明或提供多种可选实现，而不是擅自选择可能破坏现有设计的方案。

- 优先保证代码正确性、可读性与可维护性，其次才考虑性能或简化实现。

- 所有示例代码必须是可编译、可运行或逻辑自洽的，不得给出明显无法工作的片段。

- 对关键修改点应给出简要说明，说明修改目的与影响范围，便于理解和回溯。
